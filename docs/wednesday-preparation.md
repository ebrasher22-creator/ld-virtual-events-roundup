# Production Wednesday preparation and Jarvis handoff

The authoritative generator is `.github/workflows/weekly-publishing.yml` on protected main, Wednesday 07:00 America/Chicago. Jarvis reads at 08:00 in the existing private Cloud environment; see [task setup](jarvis-task-setup.md) and [production operations](production-operations.md). GitHub scheduling can queue: missing or late output must return NOT READY, never reuse a prior day's packet.

Production inputs are `weeks/current-handoff.json`, the matching weekly `editorial-report.json` and `linkedin-post.md`, plus the hash-bound canonical records and registration checks. Fetch current main and read one immutable clean commit. Run `python3 scripts/jarvis_handoff.py` without overriding the current date. The validator checks the upcoming Sunday–Saturday, today's Chicago generation date, matching report timestamp/status/counts, source hashes, qualification and exact caption.

For November 25, 2026, the required roundup is `2026/RW49_2026-11-29_to_2026-12-05`, generated on November 25 Chicago time. The current off-cycle pilot cannot satisfy this future requirement. The scheduled generator must produce a fresh packet that morning.

Weekly `jarvis-handoff.md` is a superseded manual pilot path, not read or generated by production. Its earlier five-event snapshot is preserved under [historical pilot](../reports/history/pre-production-wednesday-pilot/rw49-jarvis-handoff.md); the old preparation instructions are archived alongside it. Work-caption handoffs under `reports/work-editorial/` are also separate optional/historical artifacts, not the production pointer.

Qualification remains automatic with current primary-source checks. Only Eddie's final caption review and manual LinkedIn publication are human checkpoints. Learning Guild pending status, schedules and historical review decisions are unchanged.
